## Immediate Phase 1 checklist

1. Choose an isolation design and threat model **with the operator**; prove denied access from agent tools *and* package/test code. Pi's no-approve flags and process-group killing are not a sandbox. Capture reproducible demonstrations and limits in `docs/harness-compatibility.md`.
2. Build a source-adaptation fixture and a no-agent resolver baseline. Run a bounded live pi attempt only on a disposable non-sensitive checkout; compare actual edits, attempts, outcomes and verification, including a failed agent response/candidate.
3. Extend negative tests and reporting where the current evidence is weaker: changed advisory aliases or severity, uncollected/altered tests, deadlines including in-flight commands, and publication prerequisites. Avoid conflating simulated fixture success with a real audited candidate.
4. Review evidence and **decide** whether agent value and isolation justify Phase 2/3. If not, keep a deterministic supervised CLI and block writes.

## Scope and decision notes

- Phase 0 adopted **pi 0.99.1 + uv 0.12.12 + CPython 3.12.14 + pip-audit 2.10.1**, one Python pilot, public PyPI wheels, default runtime dependencies only (no selected groups/extras), and at most three durable *pi CLI invocations* per operation. Model/provider/auth selection remains in pi.
- Policy rejects major or 0.x-minor migrations, unrelated dependency declarations, forbidden paths and settings. Transitive parent migrations, broad ecosystem support, production-source runs, and publish/Jenkins commands are not Phase 0 features.
- Policy requires target advisory resolution with full inventory-matched audit coverage and **no new reported advisory/package identities**; unchanged unrelated findings may remain but must be reported. A passing scan is time-specific, not a proof of comprehensive safety.
- Keep the original [proposal](../Security_Remediation_Proposal.md), [technical design](../Security_Remediation_Design.md) and [brief](../Coding_Agent_Implementation_Brief.md) as historical specifications; their examples and future integrations are **not statements of installed behavior**.

# Pi compatibility and security boundary (local pilot)

Tested with `pi 0.99.1`, `uv 0.12.12`, uv-managed CPython `3.12.14`, and `pip-audit 2.10.1` on macOS ARM. The runner requires these exact installed versions; `pyproject.toml` and `uv.lock` pin its Python dependencies. The pilot pins `>=3.12,<3.13` and has **no selected groups or extras**.

`pi --mode json --no-session --no-context-files --no-extensions --no-skills --skill <trusted SKILL.md> --no-approve --tools read,bash,edit,write -- '<prompt>'` is the one-shot invocation. Prompt explicitly begins `/skill:vulnerability-remediation`. JSONL stdout is streamed into a temporary bounded log (12 MiB checked after exit); the runner requires `agent_settled`, an error-free terminal assistant message, and a separately validated final `{assessment, plan}` JSON object. JSON mode's process exit alone does not prove success. The skill is not an authorization layer; output is revalidated. Timeouts kill the Pi process group; a process which escapes that group is not contained by this mechanism. Installed pi may itself perform automatic retries within one reserved runner invocation; the three-call limit counts **CLI invocations**, not model requests/tokens. Model choice and credentials remain in Pi's own configuration.

A one-shot **no-tools** smoke test with the explicit skill returned `agent_settled`, stop reason `stop`, and the requested JSON response. This establishes printless headless invocation and skill routing, **not** that an agent-generated patch or a container sandbox was tested. Routine tests fake agent output and do not call a paid model.

**No enforceable worker isolation:** Pi runs on the host, with access to its saved provider credentials and files allowed to that OS user. Tests and dependency installation also run on the host; filtering environment variables, temporary HOME, project-trust flags, process groups and path validation are not sandbox boundaries. A malicious package, agent tool, or test could inspect runner state or other host resources; never use this mode on untrusted production repositories. Docker is installed locally but its daemon was unavailable at design time. Before unattended use or PR publication, establish a disposable worker with restricted mounts/egress/resources and prove target commands cannot access state, GitHub/model credentials, host Docker socket, or the original checkout. No publisher or Jenkins code is included.
